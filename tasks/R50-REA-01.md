### 3.1 【定论】`InfinityDimensionState.h(Z)V` = Web `buyMax(auto)`，**不是** buySingle

**结论：`h(Z)` 等价 Web `buyMax(auto)`；`i()` 才是 `buySingle()`。当前 `tryBuyId1` 只调 `h(Z)` → 永远不会解锁 ID。**

五条证据（`base_decoded/smali/kajfosz/antimatterdimensions/dimension/infinity/InfinityDimensionState.smali`）：

| # | 证据 | 行号 |
|---|---|---|
| 1 | 先算 `剩余可买数 = x()(purchaseCap) - y()(baseAmount/10)`，再按 EC8 上限钳制 | `:1454-1541` |
| 2 | 用 `Li92;`（= Web `LinearCostScaling`）算 `(count:J, costMult:BigDouble, totalCost:BigDouble)`，构造参数正是 `(当前货币, cost, costMultiplier, 可买数, …)` | `:1544-1579` |
| 3 | `count <= 0` 直接返回（`:1592 cmp-long` + `if-lez`），与 Web `buyMax` 的「一个都买不起就返回」一致 | `:1592-1596` |
| 4 | 一次性扣 `totalCost`，然后 `cost.multiply(costMult)`、`amount.add(10*count)`、`baseAmount += 10*count` | `:1604-1656` |
| 5 | `Z` 只影响静默/弹窗（`if-nez p1`），不影响买多少 —— 与 Web `if (!auto) tryShowWarningModal()` 同构 | `:1441-1449` |

对比 `i()V`（buySingle）：固定 `baseAmount += 10`（`:1892`），没有 count 计算，且**首行就是 `if (!isUnlocked) { M(); return; }`**（`:1724-1737`）。

**关键差异（决定 ID 增长手段）**：
`h()` 的第一句是 `if (!D()) return;`（`:1354-1362`）；`D()` 内含 `if (!isUnlocked) return false`（`:608-612`）。
→ **未解锁时 `h()` 直接返回，一个都不买，也绝不会解锁。**
→ `i()` 会顺带解锁（走 `M()`）。

**推荐调用序（对齐 Web `InfinityDimensions.buyMax()`，`infinity-dimension.js:398-409`）**：

```
for tier in 1..8:
    if (!d.G())  d.M()              # G()=isUnlocked, M()=unlock（Web: dimension.unlock()）
    if (d.G()):
        if (d.y() == 0L) d.i()      # y()=purchases(=baseAmount/10)，Web: if (purchases===0) buySingle()
        d.h(true)                   # buyMax(auto=true)
```

`Z` 实参取 `1`：自动购买器 `InfinityDimensionsAutobuyerState.smali:419 const/4 v4, 0x1` → `:518 h(1)`；UI「买最大」按钮取 `0`（`MainActivityInfinityDimensionsKt$loadViewsInfinityDimensions$2$1.smali:135 const/4 v1, 0x0`）。

> 附带：`tryBuyId1` 现走 `h()` 而不先 `M()`，即使 `maxAM` 修到 1e1100 之后，**只要不是玩家手动点过解锁，仍然 0 购买**。这是与 `if-le` 极性 bug 独立的第二道坑。

### 3.2 【定论】`OrekiEternity.smali` 的 `if-gt v2, v3` 应改 `if-ge`

位置：`scripts/payload/smali/kajfosz/antimatterdimensions/oreki/OrekiEternity.smali:255`（`buyNormalStudies` 的 `:id_loop`）。

- **不是有意为之**：循环体是标准 for 形态，末尾 `add-int/lit8 v2, v2, 0x1; goto :id_loop`，体内没有任何「最后一轮收尾」逻辑。
- **原版同构循环一律用 `if-ge`**：
  - `base_decoded/smali/kajfosz/antimatterdimensions/a.smali:13336`（原版 `tryAutoUnlock`：`array-length v6` + `if-ge v9, v6, :cond_44`）
  - `MainActivityInfinityDimensionsKt$loadViewsInfinityDimensions$2$1.smali:135` 附近（`if-ge v2, v0, :cond_1`）
- **严重度修正（重要）**：Android 的 `SparseIntArray.keyAt(index)` 只有 `index >= mSize && UtilConfig.sThrowForEmptyArrays` 时才抛，而 `sThrowForEmptyArrays` **默认 false**（仅 host 测试为 true）。所以 `keyAt(size)` **不会崩**，会读到未初始化槽位、返回 `0`。
  即实际后果 = **多跑一轮、把 key `0` 当时间研究 id 传下去**（`blocked(0,…)`、`l43.a(0)`），而不是必崩；且整块被 `.catch Ljava/lang/Throwable;`（`:281` 附近）吞掉。
  → 仍应改成 `if-ge`：低风险、有明确原版对照，且能消除「误买 id 0 / 误判 blocked」的不确定性。

### 3.3 【纠正】`BigDouble` 是**可变**对象，`add/multiply` 原地修改并 `return this`

`base_decoded/smali/kajfosz/antimatterdimensions/BigDouble.smali`：
`multiplyParts(DD)` 末尾 `iput-wide v0 → mantissa` / `iput-wide p1 → exponent` / `return-object p0`（`:2039` 段内）；
`add(D)` → `addParts(DD)` 同一形态（`:947` / `:3442`）。

→ `cost.multiply(mult)` 虽然 smali 里没有 `move-result`，**实际已改写 `cost`**；`amount.add(10)` 同理。
→ 因此 `InfinityDimensionState.i()`/`h()` **不是**「买入后价格不涨」的 bug，不要往这个方向查。
（副作用提醒：任何 `sget-object Llu;->xxx` 的常量**绝不能**直接当 `add/multiply` 的接收者，所以原版到处用 `copy()`。）
