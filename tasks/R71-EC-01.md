## 一、大坍缩三种触发模式

### 根因

`src/core/autobuyers/big-crunch-autobuyer.js` 的 `isUnlocked` 是**每帧都被读**的 getter，
里面带着 AU4b 归一化：

```js
if (unlocked && mode === AMOUNT && Decimal.lt(amount, 10)) { mode = X_HIGHEST; xHighest = new Decimal(10); }
```

⇒ 玩家选中 AMOUNT 且 `amount < 10` 时，下一次 UI 读取就改回去 ⇒ 表现为「点了就弹回 / 点不动」。

### 修法

改成一次性迁移：`!this._au4bNormalized && this.data.lastTick === 0` 才迁移。
`lastTick === 0` 这一条保证**重启读档也不会重跑**（跑过一次就永久 > 0）。

### 回归

`scripts/check_crunch_modes.mjs`，14 项，**直接执行 getter 源码**（切方法体 + `Function.call`）：
首次归一化一次、改回不被弹、`lastTick>0` 三种模式都留住、重启读档保持、连续切换不残留、
不碰 time/interval/isActive/increaseWithMult。

### Android

原版 Kotlin 的 `CrunchAutobuyerState` **没有**这段归一化（本作只做 AU4c 的 isActive 一次性启用），
因此同一路径不存在。本轮**没有盲改 Compose UI**。
