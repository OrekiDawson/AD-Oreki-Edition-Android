## 六、执行过程中的一次真实事故与处置

**事故**：为验证 `deploy_pages.py` 的流程可执行性，在工作区对部署仓库执行了一次**不做提交**的同步。结果：`web/_deploy/site` 出现 **47 个文件的整文件 diff**（`src/game.js` 3108 行、`src/core/reality.js` 1688 行全变），全部是换行差异（源码仓库 `.gitattributes` 的 `text=auto` 让部分文件检出为 CRLF，而部署仓库索引是 LF）。

**处置**：`git stash` → `git checkout -- index.html public src/` → 只从 stash 取回 `README.md` → 删除 stash。**当前部署仓库仅有 `README.md` 一处改动**，47 个副作用文件全部还原到 HEAD，未提交、未推送。已用 `git status --porcelain` 复核。

**结论**：这是一次**验证行为越界**（把只读验证做成了写操作），已如实记录。同时把它作为一条真实事实写进 Pages README 的「已知风险」：两个同步脚本对换行基线的处理不一致，同步前必须先看 `git diff --stat`。**未修改脚本** —— 改部署工具属流程变更，需单独授权。
