## 一、任务目标

修复 `tryBuyId1` 中确定性的条件跳转极性错误：`if-le` 使 1→8 的升序循环在第一次判断即退出，
循环体一次都不执行，整个方法退化为 `return-void`。修复后需**证明循环体确实执行了 8 层**。

## 二、缺陷事实（已核实）

`android/AD_Oreki_Edition_Android/scripts/payload/smali/kajfosz/antimatterdimensions/oreki/OrekiStageAuto.smali`

```smali
    const/4 v1, 0x1
:oreki_sa_id_loop
    const/16 v2, 0x8
    if-le v1, v2, :oreki_sa_id_done     # v1=1, v2=8 ⇒ 1<=8 恒成立 ⇒ 立即跳出
```

`if-le v1, v2` 语义为「v1 ≤ v2 就跳转」。初值 1、上界 8，第一次判断即成立。
升序闭区间 `1..8` 的正确循环头是「v1 > 8 才退出」，即 `if-gt`。

**影响面**：`ID1.isUnlocked` / `bought` 长期为 false 的直接原因是本方法从未执行，
此前「AM 未达 1e1100 所以没解锁」的解释不成立（见 INDEX 已作废条目）。

## 三、执行范围

| 文件 | 改动 |
| --- | --- |
| `oreki/OrekiStageAuto.smali` | ① `if-le` → `if-gt`，跳转目标改为新增 `:oreki_sa_id_exit`；② 新增静态字段 `sIdLoopLogged:Z`；③ 新增 `:oreki_sa_id_exit` 取证块 |

**只改这一个文件**。不碰 Web、不碰 `OrekiEternity.smali`（其边界问题待 android-agent 确认意图后再定）。

## 四、已实施改动（代码对照）

**改前**
```smali
    if-le v1, v2, :oreki_sa_id_done
```

**改后**
```smali
    if-gt v1, v2, :oreki_sa_id_exit
```

**新增取证块**（位于 `:oreki_sa_id_next` 的 `goto` 之后）
```smali
    :oreki_sa_id_exit
    const/16 v2, 0x9
    if-ne v1, v2, :oreki_sa_id_done      # 只有 v1 递增到 9 才继续
    sget-boolean v2, L...OrekiStageAuto;->sIdLoopLogged:Z
    if-nez v2, :oreki_sa_id_done         # 已打过就跳过
    const/4 v2, 0x1
    sput-boolean v2, L...->sIdLoopLogged:Z
    const-string v2, "OREKI_ID_LOOP"
    const-string v3, "tier 1..8 executed"
    invoke-static {v2, v3}, Landroid/util/Log;->i(...)I
    :oreki_sa_id_done
    return-void
```

**为什么要加取证**：原有 `OREKI_ID` 日志只在某层 `p()` 为真（门槛达成）时才打。
新档早期 8 层全未达标 ⇒ 日志一条也不会出现 ⇒ **无法区分「循环跑了但没达标」和「循环根本没跑」**。
A10 的极性 bug 正是靠这个盲区藏住的。`OREKI_ID_LOOP` 只有在 `v1` 走到 9（跑完 8 层）时才打一次，
是「循环体真的执行过」的直接证据。

## 五、同类问题排查（用户要求的第 4 条）

用脚本扫描 `oreki/*.smali` + `Oreki*.smali` 中所有「存在向后 goto 且计数器递增」的循环头，共 14 处。
判定规则：升序循环头必须是 `if-ge`（开区间 `i < n`）或 `if-gt`（闭区间 `i <= n`）。

| 位置 | 写法 | 结论 |
| --- | --- | --- |
| `OrekiStageAuto:651` | `if-le` 升序 | ❌ **唯一错误，已修** |
| `OrekiStageAuto:383` | `if-ge v0, size` | ✅ 开区间遍历 List |
| `OrekiStageAuto:570` | `if-ge v1, 0x10` | ✅ 封顶 16 次 |
| `OrekiStageAuto:870` | `if-ge v5, len` | ✅ 遍历数组 |
| `OrekiAchAudit:104` | `if-ge` | ✅ |
| `OrekiEternity:112` / `:168` | `if-gt` | ✅ 闭区间 |
| `OrekiEternity:255` | `if-gt v2, v3` | ⚠️ 边界问题，**未改**（待确认意图） |
| `OrekiChallengeAuto:317/522/597/687` | `if-gt` / `if-ge` | ✅ |
| `StageAssist:808` | `if-ge` | ✅ |

`OrekiEternity:255` 的性质不是极性而是边界：`SparseIntArray` 合法下标为 `[0, size-1]`，
`if-gt v2, v3` 会在 `v2 == v3` 时执行 `keyAt(v3)` 越界抛异常，被外层 `try/catch` 兜住后 `return`。
0..size-1 已处理完，功能上没漏，仅每次多抛一次异常。**按用户「只修有明确证据」的要求，此处置为待确认，
需 android-agent 说明原意后再决定是否改为 `if-ge`。**
