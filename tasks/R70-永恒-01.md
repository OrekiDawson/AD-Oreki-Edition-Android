# R70-ET-01　首次永恒：改用原版协程启动器

状态：**代码已改并进入构建**（验收以 `eternities` 0→1 为准，见文末）

## 一、问题

R65~R69 五轮，Android 侧自动永恒始终「入口被调用、日志无异常、`eternities` 恒为 0」。

## 二、根因（读码定案）

`prestige/c.c(...)` 是 **suspend 函数**：

```
instance-of v0, p5, Eternity$eternity$1     ; 是「自己人」才走恢复路径
if-eqz v0, :cond_0
    ...复用状态机
:cond_0
    new-instance v0, Eternity$eternity$1 ; <init>(this, p5)
```

R65~R69 传的都是自造的 `OrekiEcContinuation` ⇒ `instance-of` 为假 ⇒ 每次新建状态机 ⇒
方法体遇到挂起点 `return COROUTINE_SUSPENDED` ⇒ **调用方是同步代码，没人恢复它**
⇒ 无异常、无结算。

结论：不是「参数不对」，是「没有协程驱动器」。

## 三、修法

复用原版 `c.b()` 在「确认关闭」时的 `:cond_7` 分支：

```smali
new-instance v0, Lkajfosz/antimatterdimensions/prestige/Eternity$confirmEternity$4;
const/4 v1, 0x1
const/4 v2, 0x0
invoke-direct {v0, v1, v2}, Lkotlin/coroutines/jvm/internal/SuspendLambda;-><init>(ILvh0;)V
const/4 v1, 0x1
invoke-static {v0, v1}, Lkajfosz/antimatterdimensions/g;->p(Lvi1;Z)V
```

- `Eternity$confirmEternity$4.invokeSuspend` 只做 `c.d(..., mask 0xF)`，是真正的 SuspendLambda；
- `g.p` = `MainActivity.launchOnGameScope`，用游戏自己的 scope 驱动，挂起点能恢复；
- 第二参传 `true`：`false` 会先查 `a.o(0)`（暂停 / 反作弊冻结），命中就静默 `return-void`。

## 四、同时补齐

1. **防重入**：`sEtPending / sEtTtl / sEtBefore`，发起后比对 `log10(eternities)` 变化，
   600 帧兜底释放。不重复发起、不永久卡死。

   （`elapsedRealtime`），超时置一次性闩锁 `sRu10GaveUp`。与 Web `holdForRealityUpgrade10` 等价。
