baseline/
├── version-config.json          版本差异唯一登记处（构建脚本读它）

工具为 Rust 实现（`baseline/tools`，cargo 1.99.1 / rustc 1.99.1），五个子命令
`update / verify / diff / status / rollback` 全部实测可用。

全部自实现，避免供应链与版本漂移。

## 七、未完成与阻塞（如实记录）

1. **3.21 的 MOD 别名表不完整**：23 条里只有 5 条能用「super + 方法数 + 字段数 + 方法名集合」
   唯一确定（`bq0→iq0`、`fd0→ld0`、`fw→iw`、`iu→lu`、`k5→l5`）。
   其余 18 条在 3.21 中存在多个结构同构候选，**无法自动判定**，包括关键类
   `gi3` / `fi3` / `th3`（START 天赋三元组）、`w50`（挑战父类）、`aw`（Currency 基类）。
2. **3.21 逐补丁锚点需重新对位**：即使别名补齐，仍有补丁在新的锚点处失败
   （实测停在「记录归一化锚点不唯一」）。这属于 §73.4「不得机械套用旧补丁」的正常代价。
3. **Web 3.21 源码不存在**：官方仓库未发布，无法建立 Web 侧基线。
4. **3.21 运行验收完全未做**：没有可用构建产物。

**结论**：3.21 的**基线**已建立且可验证、可回滚；3.21 的**MOD 迁移**需要独立一轮，
按 §73 的流程逐类核对 ABI 与锚点。本轮不把 3.20 冒充成 3.21，也不产出半成品 APK。
