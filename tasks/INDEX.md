## 维护约定

- 主 Agent 建单、分派、验收；子 Agent 只回写自己那一份。
- **同一文件同一时间只允许一个 Agent 修改**，冲突写进任务单的「禁止修改」栏。
- 任务单写入不代表完成，以代码 + 实测证据为准。

## 任务单模板（AGENTS §55 / §56 要求，2026-11-01 起强制）

新建任务单必须含下列字段，缺项即不合格。

### 元信息（七项，**2026-11-01 16:53 起按 §60 单 Agent 模式执行**）

> 旧的「创建者 / 负责 / 实际执行者 / 更新者 Agent ID / 贡献者」五栏自 `AGENTS.md §60` 起废止——
> 项目只剩一个主 Agent，这些栏位不再有区分意义。存量 R50/R51 任务单不回改，只在此注明。

| 项 | 说明 |
| --- | --- |
| 任务编号 | `R51-XXX-NN` |
| 创建时间 | 真实系统时钟，格式 `2026年11月1日 15:11`，不得推测 |
| 执行者 | 固定 `main`（主 Agent，单 Agent 模式） |
| 优先级 | P0~P6，见 `RULES_INDEX.md §2` |
| 状态 | 待开始 / 进行中 / 阻塞 / 待验收 / 已完成 / 已作废 |
| 来源 | 用户执行令原文或上游任务号 |
| 禁止修改 | 仍需写明（防误改用户或其他来源的未提交内容） |

### 生命周期（三阶段，**§60 单 Agent 模式**）

| 阶段 | 含义 | 对应索引状态 |
| --- | --- | --- |
| 待开始 | 任务单已写入并提交，尚未动手 | 待开始 |
| 进行中 | 有实际动作（代码 / 构建 / 测试 / 部署） | 进行中 |
| 已完成 | 有实测证据，主 Agent 自验通过 | 已完成 |

> 旧的「已发送 / 已接收 / 已开始」是 Agent 间投递语义，§60 起废止——不再有接收方确认这一环。

### 后台构建汇报六项（AGENTS §55.4，按 §60 去掉 Agent 字段）

构建目标与任务编号 / 构建命令 / 进程 PID 或任务标识 / 日志文件路径 / 启动时间 / 当前状态（未完成一律「构建中」）+ 后续验证步骤。

**只提交启动命令不算已启动**；**APK 文件存在不等于构建成功**（须走 §55.6 七步）。

### 文体（AGENTS §51）

禁第一人称：不得出现「我 / 我们 / 我认为 / I / We / My / Our」。

> 注意：任务单内若写了第一人称扫描命令，命令本身会被扫中，属假阳性，按行号人工剔除。
