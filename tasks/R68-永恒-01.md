# R68-ET-01　首次永恒：坍缩闸门死锁

状态：已修复，待装机验证
关联：FACTS C.115、AGENTS §6.5.2、教程附录 F §七

## 一、现象

`eternities` 长期为 0，`EP` 为 0，即使：

- 已打破无限（`breakInfinityUpgradeBits = 511`）
- 无限点数 2.2e30（远超 ID1 的 1e8 门槛）
- `thisEternity.maxAM` 已在 1e300 量级

同一时刻的三次采样（间隔 25 s，均取自 `/data/data/.../files/player.json`）：

| 采样 | 当前 AM | thisEternity.maxAM | thisEternity.maxIP | infinity 次数 |
|---|---|---|---|---|
| t1 | 3.594e300 | 1.378e300 | 1.604e30 | 7.565e6 |
| t2 | 1.646e300 | 1.779e300 | 1.918e30 | 7.722e6 |
| t3 | 2.912e300 | 1.964e300 | 2.233e30 | 7.880e6 |

**关键判读**：`infinities` 每 25 秒稳定增长约 1.6e5，说明**坍缩仍在每 1 秒触发**；
于是 `maxAM` 只能反映「1 秒产量」，永远停在 1e300 量级，到不了 1.797e308。

## 二、原版判定的真实字段（REA 逐条核对）

| 方法 | 实现 | 语义 |
|---|---|---|
| `Player$ThisEternity.h()` | `iget maxAM` | 本永恒期反物质峰值 |
| `Player$ThisEternity.i()` | `iget maxIP` | 本永恒期无限点数峰值 |
| `prestige/c.f()Z` | `ThisEternity.i()` vs `c.h()` | **永恒资格** = maxIP ≥ requiredIPForEP(1) |
| `prestige/c.g()` | `ThisEternity.i()` → log10 → Pow | 永恒可得 EP |
| `prestige/c.b()V` | 首句 `if (f())` + 完整重置 | 原版「按永恒」按钮的同步入口 |
| `InfinityDimensionState.p()Z` | `(eg3.r.k() \|\| maxAM ≥ 本层门槛) && v()` | **ID 层是否已解锁**（不是永恒资格） |
| `eg3.r.k()` | 单条 Perk 旁路 | 只是 p() 的一个子条件 |

结论：永恒资格看的是 **maxIP**，而 maxIP 只在坍缩时刷新；要让它到 1.797e308，
必须先让 **maxAM** 冲到 1.797e308。二者是先后关系，不能混用。

## 三、根因

`OrekiStageAuto.holdCrunch()` 的最后一个条件是 `InfinityDimensionState.a(1).p()`
（ID1 是否**已解锁**），且写法是「p() 为真 → 不暂停」。于是：

1. ID1 未解锁 → p()=false → 暂停坍缩（此时正确）
2. ID1 一旦解锁 → p()=true → **永久放开坍缩**
3. 坍缩每 1 秒清零反物质 → maxAM 卡在 1e300 → maxIP 卡在 1e30 → `f()` 恒 false
4. `tryEternity` 因 `f()` 为 false 直接返回 → 永远不永恒

这是一个**自锁**：保护窗口的解除条件依赖一个只有「不保护」才能达成的状态。

补充排除项：不能把闸门改成 `f()`。因为 `f()` 依赖 maxIP，而 maxIP 只在坍缩时刷新；
暂停坍缩 → maxIP 不刷新 → `f()` 恒 false → 二次死锁。

## 四、修复

`holdCrunch()` 的第四条件改为「反物质峰值 vs 1.797e308」：

```
maxAM < 1.797e308  → 继续暂停坍缩，让反物质往上爬
maxAM ≥ 1.797e308  → 立即放开，这次坍缩把 maxIP 推到 1.797e308
                     → f() 为真 → tryEternity 按原版 c.b() 完成永恒
```

常量 `0x7fefffffffffffff` = `Double.MAX_VALUE` = 1.7976931348623157e308，
与原版「无限反物质」门槛一致。

不改任何写入路径：仍然只调用原版 `prestige/c.b()V`，由它自己算 EP、重置、
更新记录。mod 侧不写 eternities / EP / 解锁位。

## 五、回归守卫

`scripts/fixture_eternity_gate.py` 新增 4 条（共 15 项）：

- `holdCrunch` 必须读 `Player$ThisEternity;->h()`（maxAM）
- 必须出现 `0x7fefffffffffffff`
- **不得**再出现 `InfinityDimensionState;->p()`
- 到门槛后必须 `if-gez v0, :oreki_sa_hc_no`（cmp ≥ 0 放开）
