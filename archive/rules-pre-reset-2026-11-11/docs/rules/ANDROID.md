# Android 实现与分析

本文件只保留 Android 生产、反混淆、基线迁移和真实验收规则。

## 1. 业务实现

### 1.1

Android 新增或修改业务逻辑必须使用 Kotlin，并完成 Kotlin → kotlinc → D8 → DEX → APK 链路。不得新增 Java/Smali 业务逻辑；必要的原版 ABI、第三方二进制和兼容层必须说明文件、调用关系、限制原因和替代方案。

### 1.2

保留原业务语义、数据结构、方法签名和字段类型；新类、方法、变量和注释使用清晰的中文业务语义。混淆符号只允许出现在有证据的绑定和兼容边界。

### 1.3

独立 `classes.dex` 不等于 APK 集成。必须验证 D8 输出、最终 APK DEX、签名和真实调用路径。

## 2. 基线与 ABI

### 2.1

基线识别必须依据实际 APK/XAPK、Manifest、DEX、真实类/方法/字段、ABI、签名和运行证据。禁止使用 alias、旧版本映射、名称猜测或位置投票代替识别；`activity-alias` 必须核对启用状态、目标组件和实际启动组件。

### 2.2

`baseline/versions/<版本>/bindings.json` 是绑定入口。只有描述符、宿主锚点和版本证据充分一致的绑定才允许进入构建；歧义、冲突或缺证据时必须阻断。

### 2.3

每个版本保留来源、包名、版本号、证书 SHA-256、APK SHA-256、大小和取得时间。版本差异集中写入基线配置和报告，不复制整套版本构建脚本。

## 3. 反编译与分析

### 3.1

需要反编译时先确认当前 APK 身份，再使用 REA、JADX、DEX 工具或等价工具检查包、类、方法和引用。记录命令、证据标识、APK SHA-256、关键签名和结论。

### 3.2

复用当前轮已完成的导出和分析，不重复覆盖重要目录；工具失败、provider 不可用或输出截断必须如实记录，不能据此推断实现不存在。

### 3.3

分析工具、核心配置和可复现成果应纳入 Git；大型原包和导出按实际恢复价值放入独立受控存储，不进入普通源码路径。

## 4. 运行与 GUI 验收

### 4.1

按改动风险执行定向验证；基线升级或高风险修改执行必要完整回归，覆盖补丁、机制、原版结算、挑战、存档兼容、多 DEX 和获准设备运行。

### 4.2

frame-observer 优先用于真实屏幕观察。静态引用、日志、节点存在或独立夹具不能代替实际 GUI 状态。

### 4.3

保持 Android 深色模式、原版导航、Current Tab 和子页签标题；不得自造合成顶栏。教程和玩家可见术语按 `TUTORIAL.md` 执行。

## 5. 存档与安全

### 5.1

新档验收使用独立 AVD、独立 userdata 和明确的 ADB serial；玩家存档与只读 savestates 不得触碰。非 debuggable 包的限制不构成清理旧档授权。

### 5.2

测试前记录 APK、设备和存档策略；测试后记录是否恢复存档、停止后台任务和保留证据。任何真实运行失败都必须标记为 `FAIL` 或 `BLOCKED`，不能静默计为成功。
