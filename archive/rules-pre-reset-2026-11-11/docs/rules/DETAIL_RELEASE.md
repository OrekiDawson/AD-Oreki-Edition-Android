# 发布细则

本文件补充 [RELEASE](RELEASE.md)，只保留当前构建、验证和共享资源的执行要求。

## 1. 构建节奏

### 1.1

集中处理同一批相关修改，再执行必要构建和验证；不因单个文档改动触发无关 APK 构建。

### 1.2

候选构建可按实际开发需要重复执行，但每次都必须绑定当前源码输入和对应 APK。输入未变且已有可用产物时可以复用，不得用重复构建代替验证。

### 1.3

正式构建前确认工作区、签名输入、基线绑定、工具链和输出目录；保留可回滚产物，不覆盖稳定包。

## 2. 验证证据

### 2.1

语义夹具、契约检查和静态 DEX 检查用于快速定位；它们不能替代真实 APK 安装、运行和 GUI 证据。

### 2.2

影响界面或游戏状态的修改必须记录实际 APK 身份、存档策略、设备、操作步骤、操作前后截图和关键结果。日志只能作为辅助证据。

### 2.3

候选、稳定版、阻塞和未执行结果必须分开记录；未通过真实门禁的产物不得写成稳定版。

## 3. 共享设备

### 3.1

Android 与 Web Chrome 共用一台测试设备时严格串行。切换用途前停止前一个目标包；长跑测量期间不得停止目标包或清除数据。

### 3.2

设备序列号、分辨率、服务器地址和工具路径以当前环境为准，不把个人电脑路径写入通用规则。

### 3.3

正式构建、共享 AVD 和真实输入操作由一个明确的协调者串行管理；其他 Agent 可以只读分析证据，但不得并发操作设备。

## 4. 时间与异常

### 4.1

发布报告记录各阶段开始时间、结束时间和耗时；不得只给总耗时或用旧记录替代当前记录。

### 4.2

阶段超时先定位具体阻塞，不盲目重复构建、部署或轮询。一次修复尝试仍失败时保留有效产物，报告阻塞并转做其他安全工作。
