# Git、共享文件与工作区保护

本文件只保留当前 Git、共享文件、硬链接和工作区保护规则，适用于 Android、Web、frame-observer 和部署仓库。

## 1. 开工检查

### 1.1

开工前核实实际仓库、分支、HEAD、远端、未提交/暂存修改和远端差异；没有实际修改的仓库不创建空提交，不猜测 remote。

### 1.2

共享规则、硬链接和重要文件修改前检查实际路径、inode、nlink、Git 跟踪状态、使用方和必要哈希；采用保链原位编辑。

## 2. 修改与提交

### 2.1

禁止 force push、`git reset --hard`、`git clean`、丢弃已有修改、覆盖远端历史或删除用户存档。遇到冲突保留现场并报告。

### 2.2

只暂存本轮相关文件，提交前检查 staged diff。提交 subject/body 使用中文，技术类名、命令、文件名和代码符号可保留原文。

### 2.3

并行工作使用独立 worktree、Git index 或明确文件所有权；不自动合并其他任务成果。提交不等于发布，发布必须经过对应门禁。

## 3. 任务编号与规则镜像

### 3.1

任务编号只能使用当前用户 Prompt 指定的编号；不得自行新增、重排、删除、复用编号或修改历史提交标识。

### 3.2

Android/Web 同名规则视为同一套跨端契约；修改一端时检查另一端镜像和差异说明，不在单边静默建立冲突条款。

## 4. 文本格式

### 4.1

受控文本统一使用 UTF-8 无 BOM 与 LF 换行；二进制文件不得做文本换行转换。

### 4.2

共享硬链接不得被转换工具拆开；换行或编码修改前检查 inode、设备号和 nlink，修改后复核链接、路径和文件状态。

### 4.3

`.editorconfig`、`.gitattributes` 和仓库配置必须与当前 LF 约束一致；纯格式修改单独归类，不与业务改动混杂。

## 5. 交付保护

### 5.1

正式 APK、发布清单、签名密钥和上传会话由协调者独占；候选产物使用唯一身份，不覆盖稳定产物。

### 5.2

提交、构建、部署和发布报告记录真实 diff、输入、产物、哈希、验证结果和未解决阻碍；不得用提交成功或复制成功冒充正式交付。
