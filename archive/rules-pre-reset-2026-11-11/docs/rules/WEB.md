# Web 开发与轻量验收

本文件只保留 Web 生产、移动端验收和独立部署规则。

## 1. 上游与改动范围

### 1.1

Web 使用当前真实上游 commit 和源码，不追随 Android 版本号。双端行为语义一致，不要求 Web 复制 Android 的实现技术。

### 1.2

功能修改必须进入实际 Web 运行入口；报告、快照、夹具和部署副本不是源码实现入口。

## 2. 测试

### 2.1

只运行与本轮修改和受影响依赖直接相关的定向测试；核心机制、存档、循环、响应式、版本迁移或真实回归有风险时再扩大范围。

### 2.2

需要移动端验收时使用真实 Android Chrome 和当前视口；桌面 Headless 不能冒充移动端证据。记录浏览器、设备、存档和实际结果。

### 2.3

本地测试隔离浏览器 profile 和真实存档，保护 `_saves/`。失败、挂起和未执行必须分开记录。

## 3. 游戏行为

### 3.1

导航沿用原版结构，移动端保持触控与可读性。MOD 全局行动节拍与自动购买器策略节拍分离，玩家手动操作不受 MOD 节拍限制。

### 3.2

自动购买器不得强制打开玩家关闭的购买器，不得覆盖无关手动配置；玩家修改受管项后在下一次策略 tick 按最新建议恢复。

### 3.3

无限阶段隐藏永恒层内容；永恒阶段显示永恒次数和永恒点数；现实内容只能在真实现实结算后显示。

## 4. 构建与部署

### 4.1

优先使用现有依赖和离线工具链，不擅自升级无关依赖。模块校验必须使用项目实际 bundler/测试链，不能只凭单独 `node --check` 判断整体结果。

### 4.2

Pages 只在必要验收通过后部署，并检查实际线上页面、资源和关键功能。Android 阻塞不自动阻止独立 Web 交付，但两端证据不得互相冒充。
