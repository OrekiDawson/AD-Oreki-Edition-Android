# 工具链与环境

本文件只保留当前工具、环境、网络和共享资源规则；具体版本、路径和一次性实测放入 FACTS。

## 1. 工具选择

### 1.1

优先复用当前可用的 JDK、Android SDK、Gradle、Kotlin、D8、aapt2、apksigner、adb、Node.js、Rust 和项目脚本；先检查实际路径、版本和可执行状态，不重复安装。

### 1.2

安装或升级只使用当前兼容的正式稳定版，核对架构、依赖和可信来源。不得为了追求新版本破坏已有可构建环境，也不得把本机版本写死进通用规则。

### 1.3

Android 业务不得回退到 Java；Java 只作为 Kotlin、D8 和 Gradle 的运行环境。系统 Gradle 与项目 Wrapper 分开使用，Android 优先使用项目 Wrapper 的离线构建。

## 2. Linux 与 Windows

### 2.1

新开发优先在 Linux 执行；Windows 保持兼容。跨平台脚本必须说明路径、权限、换行、大小写和工具行为差异。

### 2.2

不得假设固定挂载点、个人路径或特定机器配置。涉及权限、符号链接、硬链接和大小写时，先检查实际状态。

## 3. 搜索、分析与网络

### 3.1

文本和文件搜索优先使用 `rg`；APK、DEX、ABI 和基线分析优先复用现有 REA、JADX、apktool、Rust 或 Android SDK 能力，不重复做无关全量分析。

### 3.2

网络和 SDK 下载使用可信官方源及项目当前可用路径。代理只按实际工具需求配置，凭据只存用户环境或 keyring，不进入 Git、日志、README 或报告。

### 3.3

外部资料、工具能力和环境状态以当前实际检查为准；读取失败记为未知，不猜测补造。

## 4. 资源与进程

### 4.1

内存、CPU、IO 和进程归属同时检查；保护 Harness、用户进程和其他 Agent 的任务。发现已有构建、签名、模拟器或观测进程时，先核对归属，不重复启动。

### 4.2

同一构建树、DEX 注入目录、签名密钥、APK 输出目录、AVD 和浏览器观测资源必须串行使用。候选构建使用唯一暂存目录和产物身份。

### 4.3

只停止自己拥有的进程和资源；不得杀掉用户、主控、其他 Harness、无关浏览器、Gradle 或 AVD。

## 5. 构建与验证

### 5.1

开发期优先执行 Kotlin 定向编译、必要 D8/DEX 校验、ABI 检查和相关测试；最终集成才执行 Release 构建。构建缓存可以复用，但不得跳过真实变化的输入。

### 5.2

工具链证据必须区分源码编译、DEX 生成、APK 组装、签名和真实运行。缓存命中、静态分析或独立 DEX 不能冒充完整 APK 验证。

### 5.3

环境故障记录实际命令、时间、日志和退出结果；一次修复尝试仍失败时停止重复操作，保留现场并推进不依赖该环境的工作。
