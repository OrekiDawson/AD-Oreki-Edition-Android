# Agent 并行开发与持续交付契约

本文件只保留当前协作、资源独占和交接规则；任务编号、历史状态和一次性环境事实放入任务记录或 FACTS。

## 1. 总体职责

### 1.1

主 Agent 负责目标、任务拆分、跨模块集成、共享资源协调、冲突处理、正式门禁和最终交付。

### 1.2

取得明确目标、文件所有权、输入证据和验收标准的子 Agent，可以独立完成大规模生产代码、必要重构、测试和证据采集；不得用人为行数或文件数限制替代验收标准。

### 1.3

子任务完成后保存真实 diff、验证结果、阻碍和未完成步骤；有安全且不冲突的后续工作时继续推进，没有可执行工作时才交接或释放资源。

## 2. 任务派发

### 2.1

派发消息必须包含目标、可写文件/目录、禁止修改范围、输入证据、验收标准、独占资源、交付格式和停止节点。

### 2.2

并发数量以当前 Harness 配置和实际运行状态为准，不在规则中猜测固定上限。角色数量是调度偏好，不是额外限额。

### 2.3

同一文件、模块、构建树、签名密钥、正式产物或设备同一时刻只能有一个写入/操作责任方。只读分析不取得写入所有权。

## 3. 工作区与构建隔离

### 3.1

优先使用独立 worktree、分支或可靠隔离机制；不得覆盖其他 Agent 的未提交修改、硬链接、存档、缓存和证据。

### 3.2

相同构建树、DEX 注入目录、APK 输出目录、签名密钥或基线临时目录不得并发运行 Gradle、apktool、DEX、签名或发布任务。发现已有进程先核对归属，不重复启动。

### 3.3

正式 Release、稳定版 APK、发布清单和上传会话由协调者独占管理；子 Agent 只生成有唯一身份的本地候选。

## 4. AVD 与 GUI

### 4.1

同一 AVD 的安装、停止、输入、截图、UI dump、logcat 清理和屏幕投影同一时刻只允许一个责任 Agent 操作。Android 与 Web Chrome 共用设备时严格串行。

### 4.2

其他 Agent 可以读取已保存的截图、控件树和日志，但不得向共享设备发操作。长跑期间不得停止目标包或清除其数据。

### 4.3

真实 GUI 证据必须绑定 APK 身份、设备序列号、存档策略、操作步骤和前后截图；不同候选、设备和存档的证据不得混用。

## 5. 代码与验证边界

### 5.1

Android 业务逻辑使用 Kotlin，并完成 Kotlin → kotlinc → D8 → DEX → APK 链路；Smali/Java 只保留已核实的原版兼容层。

### 5.2

Android/Web 的真实资源、购买、扣费、奖励、挑战和阶段结算必须来自生产路径，不得用夹具或静态结果伪造。

### 5.3

验证区分 `PASS`、`FAIL`、`BLOCKED` 和 `NOT RUN`；候选构建、静态检查和独立 DEX 不等于稳定版运行验收。

## 6. 交接与停止

### 6.1

交接记录当前 commit、未提交文件、真实 diff、命令、日志、产物路径、哈希、验证结果和未完成步骤；接手 Agent 复核现场后再取得所有权。

### 6.2

只能中断或释放自己拥有的任务和资源；不得杀掉用户、主控、其他 Harness、无关浏览器、Gradle 或 AVD 进程。

### 6.3

官方状态只按当前 Harness 可观察状态和实际结果描述，不自造“回收完成”等状态。需要停止时使用官方提供的中断、释放或排空能力。

## 7. 规则维护

### 7.1

修改共享规则前确认没有其他 Agent 正在写同一文件；规则修改完成后只做链接、编号、同步和冲突检查，不启动无关 APK 构建。

### 7.2

提交使用中文 subject/body；禁止强推、硬重置、清理或覆盖他人成果。提交不等于稳定版发布。
