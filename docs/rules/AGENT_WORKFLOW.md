# Agent 持续执行契约
权威：本文件；范围：主 Agent、获派子 Agent 与轮次调度；来源：原 §77.1–6、§79.1–7，替代 §60 的组织方式及重复协作条款；状态：生效。

- 触发：已获授权且存在安全、有效、可执行工作。主 Agent 同时承担生产、集成与调度，子 Agent 执行实际任务；一个子任务结束不代表整轮结束。
- 派发必须真实调用可用 Agent 工具；消息包含目标、授权文件、禁止修改、输入证据、验收、独占资源与停止节点。按实际并发限制动态轮换，不为凑数量创建空任务。
- 同一文件一个修改责任方；共享 Git index 写入隔离；同一时间一个 AVD 操作者、一个 Android 最终 Release 构建。构建输入冻结，不并行修改其输入。重型构建与重型 AVD 观测串行。
- 子任务完成或失败：保存修改与证据 → 报告 → 主 Agent 更新任务队列 → 领取不冲突的授权工作。需要新文件所有权时先交接，不自行争抢。
- 等待构建期间推进不依赖构建结果的独立工作；记录任务 ID/PID、启动时间、commit、命令、日志、状态、退出码、产物路径和哈希。确无安全工作时可交还名额。
- 清理限本轮有权管理的 Agent；先保存，不能终止其他 Harness、主控或无关进程。失联不得导致成果丢失。
- 生产问题、交付阻塞优先于无价值审计；子任务完成、测试通过、commit 或单端部署不单独构成整轮完成。
- 双小时节点按 CORE.md 理解为「稳定版发布节奏」（每两小时最多一个稳定版）：候选与中间进度不触发整轮停止，稳定版门禁未过时继续已授权开发与验证，不得以候选冒充稳定版；稳定版发布后才安全处理在途工作并停止。任务角色、ID 与阶段状态只存在任务上下文。
- **RG02-05 环境阻塞限时与并行兜底**：普通 AVD/ADB/SDK 等环境故障默认先给约 15 分钟有证据的诊断预算，记录进程归属、退出码和关键日志，不猜测原因，不重复已失败启动方式。未恢复则明确标记受阻，释放独占资源，主/子 Agent 同时转向不依赖该环境的已授权生产代码、构建或交付；仅涉及数据安全、不可逆操作或真实 P0 故障时按风险延长诊断，且不改变整轮双小时停止节点。
- **RG02-13/10 构建预算共担（主/子 Agent）**：同一轮内所有 Agent 共享同一 Release 构建预算，状态持久化在 `build/release-build-ledger.json`，换 Agent、重启 Harness、切模型、改会话名都**不重置**。子 Agent 不得擅自发起完整 Release 构建；由主 Agent 冻结输入后统一执行一次。构建记录必须区分：编译检查 / DEX 校验 / APK 组装 / Release 签名 / 最终门禁 / 紧急重建。正在执行的 Gradle 任务不得被新的检查脚本擅自杀死。
