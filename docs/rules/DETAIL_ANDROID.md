# Android 实施细则

本文件补充 ANDROID，只保留当前 Android 观测、基线、ABI 和 Kotlin 迁移要求。

## 1. 观测工具

### 1.1

Android GUI 验收优先使用 frame-observer 获取当前屏幕、控件树、事件和日志；接口失败时使用最新截图、ADB UI 层级和交叉证据，不编造坐标。

### 1.2

每次关键操作都执行：读取当前画面 → 判断弹窗和遮挡 → 定位真实控件 → 点击 → 重新观测 → 保存前后截图 → 核对页面与游戏数据。

### 1.3

frame-observer 只观测，不注入点击、不修改游戏逻辑、不绕过授权。服务异常必须记录实际原因，不无限重启共享服务。

## 2. 基线与 ABI

### 2.1

基线升级前确认 APK 身份、Manifest、DEX、ABI、证书和版本配置；使用真实描述符和运行证据，不使用 alias 或名称猜测。

### 2.2

混淆符号必须登记在绑定配置中，并保留宿主类、方法完整描述符、参数、返回值和证据来源。无法唯一确认时阻断构建或调用。

### 2.3

版本差异集中维护在基线配置和说明书；不得复制整套版本构建脚本，不得把独立 DEX 或静态引用当作最终 APK 证据。

## 3. Kotlin 迁移与命名

### 3.1

新增或修改业务使用 Kotlin；兼容层只处理已核实的原版调用、ABI、反射和必要二进制边界。

### 3.2

新类、方法、变量和注释使用职责清晰的中文语义；混淆名只出现在适配边界。修改条件时同时验证正向、反向和阈值边界。

## 4. 运行验收

### 4.1

按风险执行定向检查、构建、安装和真实 GUI 验收；影响基线或存档兼容时扩大回归范围。

### 4.2

验收记录 APK SHA-256、设备 serial、存档策略、操作步骤、截图和结果。静态门禁、日志或夹具不能替代真实运行证据。

### 4.3

结果只使用 PASS、FAIL、BLOCKED 和 NOT RUN；未完成必要门禁的产物不得称为稳定版。
