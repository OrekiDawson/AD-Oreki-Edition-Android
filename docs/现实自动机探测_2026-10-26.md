## 3. F=1 vs F=10000（3 次重复，各 30 s）

单位：字段增量 / `Δrecords.realTimePlayed`（每毫秒现实时间）。

| 字段 | F=1（3 次） | F=10000（3 次） | 比值 F10000/F1 |
|---|---|---|---|
| `mem_teresa` | 1.289e9 / 1.28909e9 / 1.28901e9 | 1.29005e9 / 1.28984e9 / 1.29008e9 | **1.0008** |
| `mem_v` | 4.44246e7 / 4.44256e7 / 4.44247e7 | 4.44581e7 / 4.44539e7 / 4.44588e7 | **1.0007** |
| `momentumTime` | 0 / 0 / 0 | 0 / 0 / 0 | — |
| `lai_darkMatter` | 0 / 0 / 0 | 0 / 0 / 0 | — |

- **重复性**：同组 3 次的离散度 ≤ **0.02%**，无随机性、无解锁抖动。
- **现实窗口**：F=1 组 ΔrealTimePlayed = 35,034 / 36,722 / 35,118 ms；
  F=10000 组 = 37,041 / 34,717 / 37,470 ms —— 窗口量级一致（±7%，来自落盘与 adb 延迟）。

### 3.1 结论（[实测]）

**Android 的 Ra 宠物记忆增长速度与全局倍率 F 无关。**
F=1 → F=10000（1 万倍）时，每现实毫秒的记忆增量变化 **< 0.1%**。

### 3.2 一个必须写清的测量陷阱

本存档的 `records.totalTimePlayed` 已达 ~1e99 量级。
double 在该量级的 ULP 远大于单帧增量（`realDiff × official × F`），
所以 **`ΔtotalTimePlayed` 完全无法分辨增量**，F=1 与 F=10000 的「游戏时间比」只反映
浮点量化噪声（显示为 ~9.7× 而非 10000×）。
→ **本轮不把 `totalTimePlayed` 作为任何结论的依据**；
「游戏时间是否 ×F」这件事**不能**用这个字段在这个存档里验证。
Ra 记忆本身只有 1e13 量级，不受此影响，测量有效。

## 4. 与 Web 对照

| 项 | Web（`AD-Oreki-Edition@470d0e88`） | Android（本轮实测） | 证据级别 |
|---|---|---|---|
| Ra 宠物记忆增量 | `Ra.memoryTick(realDiff / sqrt(F), …)` → **raw × sqrt(F)**，F=10000 时 **100×** | 增量 = 墙钟，**与 F 无关（1×）** | Web **[源证]**（`game.js:397`）；Android **[实测]** |
| 两端差距 | — | **在 F=10000 下，Web 的 Ra 记忆获取比 Android 快约 100×** | **跨端差异（方向明确）** |
| `momentumTime` | `+= realDiff × Achievement(175)`，同样是 raw×F | 未测到（momentum 未解锁） | Web [源证]；Android **[未验证]** |
| 暗物质维度 | `DarkMatterDimensions.tick(raw × sqrt(F))` | 未测到（Laitela 未运行） | Web [源证]；Android **[未验证]** |
| 黑洞 `blackHoleDiff` | `realDiff / sqrt(F)` = raw × sqrt(F) | 路径未定位，未测 | Web [源证]；Android **[未验证]** |

**必须标注的限制**：
1. Web 侧是**源码证据**，不是 Web 运行时结果（本轮不依赖 Web 实验，也未启动 Web）。
2. 「差距 100×」的严格前提是**两端的基准速率（rate 系数）相同**。
   本轮只证明了 Android 的速率不随 F 变，**没有**证明 F=1 时两端速率相等。
   若 Android 的基准速率恰好是 Web 的 100 倍，则 F=10000 时两者反而相等 —— 该情形无法用现有数据排除。
3. 因此结论只能是：**「F 的作用方式不同」已被证实；「实际进度差 100×」仍需一次 Web 运行时对照。**

## 5. 任务 B：delta 的来源与倍率证据

| 事实 | 证据 |
|---|---|
| `a;->d(DZ)V`（`a.smali:85`）是 Ra 宠物 / momentumTime / Laitela 的共同入口 | [源证] 函数首行取 `celestials/ra/a` 门面；`:466` 写 momentumTime；`:479` 取 `celestials/laitela/a` |
| 该函数内**无 `sqrt`**、**无 `OrekiSpeed` 引用** | [源证] 全函数检索；唯一除法是 `:213` 的 `/2.0`（宠物收益曲线常数） |
| 调用点 | `a.smali:11020`（主循环 `a.f` 内，实参 `{v3,v4,v7}`）、`celestials/nameless/a;->g` @2267 |
| F 注入点在下游 | `a.smali:11542-11544`（`mul-double v12,v12,v37` → `OrekiSpeed.apply`），**晚于** `11020` 的 Ra 调用 |
| **`p0` 不含 F** | **[实测]** 见 §3：F 变化 1 万倍，记忆速率不变 |
| `p0` 是墙钟毫秒而非游戏增量 | **[链推]** 若 `p0` 含 official（本存档 official ≈ 1e300 量级，见 `totalTimePlayed` 的 1e99 量级），
记忆增量会大到 1e300 量级；实测仅 1e13/30s，与墙钟毫秒一致 |
| 是否存在「调用者已放大、被调用者再除回」 | **[未验证]** 静态上未见 sqrt，但 `a.f` 内寄存器复用严重，无法排除上游其它分支 |

**为什么不能只靠静态下结论**：`a.f` 开头是协程 resume 分支表
（`Game$gameTick$1.D$0/J$0/Z$0/...` 恢复局部变量），同一 `v12` 在 `11458` 当乘数、
`11492` 当除数、`11542` 再乘 `v37`；线性扫描无法确定基本块归属。
→ 本轮改用**运行时判定**（F 切换法）绕开这个不确定性，得到的是可直接引用的行为证据。

## 6. 是否发现足以影响实际通关时间的真实差异

**是，但需限定表述。**

- **已证实（[实测]+[源证]）**：Android 的 Ra 宠物记忆获取**完全不受 F 加速**；
  Web 在 F=10000 下按 `sqrt(F)`=100× 放大。两者**机制不同**。
- **影响面**：Ra 记忆是 Ra 宠物等级与解锁的前置资源，属**真实进度**（不是统计显示）。
  在 F=10000 下，Web 玩家拿到同等记忆所需现实时间约为 Android 的 **1/100**（前提见 §4-2）。
- **未确认**：`momentumTime`、Laitela 暗物质、黑洞三条路径**本轮均未测到**，
  不能因为 Ra 一条测出来就推断另外三条"同理"。

## 7. 下一步建议

| 优先 | 事项 | 理由 | 风险 |
|---|---|---|---|
| P1 | 找 **momentum 炼金已解锁**的存档复测 `momentumTime` | 它与 Ra 记忆同在一个函数、同一个 `p0`，是最可能同结论的一条，但**必须实测** | 低（只读） |
| P2 | 进 **Laitela 现实**复测暗物质维度 | 与 Ra 同函数但独立 tick，不能外推 | 中（需构造运行态） |
| P3 | 定位 Android 黑洞增量路径 | 本轮未定位；`blackHoleDiff` 在 Web 是第三条 sqrt(F) | 中 |
| P4 | 若确认 100× 差距，**是否对齐**由"爽玩"目标决定 | 对齐方向应是**让 Android 也吃到 sqrt(F)**（更快），而不是把 Web 降速 | 需授权；属改生产机制 |

**不建议**：为了让两端代码形式相似而给 Android 加 `sqrt(F)` —— 必须先确认这是**有意设计**还是
Web 侧的历史遗留（G3，需 Web 仓库设计记录，本轮无法判定）。
