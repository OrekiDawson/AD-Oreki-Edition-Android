有效倍率实测：同一快照 `thisInfinity_time = 6.162e8`（游戏秒）对 `thisInfinity.realTime = 30,834 ms`
→ **游戏时间 / 现实时间 = 2.0e4 = 2×F**，与 R5.4 `cadence_bench` 的 2×F 口径一致（静态+运行双证）。

### 首个真实阻塞：新档零产量，且没有任何自动化

1. 开局 `反物质 10.0 / 每秒 0 / 第一维度 0` —— **不手动买第一个维度就永远没有产量**。
   这是设计如此，且教程文案已经直说：「点击'价格：10'按钮，买下你的第一个反物质维度吧！」
   → **不是隐藏条件、不需要攻略**，新手门槛合格。
2. 手动买下第一个维度后：**2 秒内 反物质 10 → 115.97K，每秒获得 3**。
   10000× 下产量爆炸，因此「点一下」几乎不构成等待。
3. 真正的问题在**后续没有任何自动化**：
   | 自动购买器 | 解锁条件（源码） |
   |---|---|
   | 维度 ×8 | `data.isBought`（1e40 × 10^(tier−1) 反物质）或 普通挑战 1..8 完成 |
   | 速度 | 同上口径（`isUnlocked` 字段） |
   | 维度提升 | 普通挑战 10 完成 |
   | 星系 | 普通挑战 11 完成 |
   | 大坍塌 | 普通挑战 12 完成 |
   → 普通挑战要先有无限；无限前一行自动化都没有 ⇒ **从开局到首次无限之间全部靠手点**，
     而这段时间在 10000× 下资源跳跃极快，手点频率跟不上，属「无趣重复劳动」而非「时间墙」。
4. 附带实测：**游玩中不自动落盘**（连续 40 s 两次 pull 得到同一份 `lastUpdate`）；
   必须 HOME/暂停才写 `player.json`。任何增量测量都必须先触发落盘，否则 Δ 恒 0 是假象。

## 3. 本轮做过并**放弃**的修复（记录以免重走）

思路：把四个自动购买器的 `isUnlocked` 门槛短路（保留 Pelle 禁用检查），让新档即有自动化。

- 实现：`scripts/build_mod.py::patch_autobuyer_unlock()`，四条各改 1 条指令：
  `AntimatterDimensionAutobuyerState.g()` / `TickspeedAutobuyerState.g()` 的 `if-nez v0,:cond_0 → goto :cond_0`；
  `DimBoostAutobuyerState.g()` / `GalaxyAutobuyerState.g()` 的 `if-eqz p0,:cond_0 → nop`。
- 构建：`./gradlew.bat check assembleRelease` **RC=0，BUILD SUCCESSFUL 6m26s，契约全 PASS**，
  四条补丁日志均在。候选产物 `9d2c8808…`（69,732,894 B）。
- **运行实测：无效。** 装到 `oreki_test`、`pm clear`、重新开局，在**截图确认无弹窗**的
  60 s 干净窗口内：反物质恒 10.0、每秒 0、第一维度 0 —— 一次都没买。
- 判定：真正的门控不在四个 `g()`，而在「每帧 tick 驱动」或「自动化页是否解锁」。
- 额外理由：R5.5 补充令要求**保留手动购买维度/升级**，开局全开自动购买器与该要求相悖。
- 处置：**已从 `main()` 撤下，不发布**；`release/反物质维度.apk` 保持 `8cc40bfd…` 未动，
  OneDrive / 小米云盘未重传。函数体保留作证据。
