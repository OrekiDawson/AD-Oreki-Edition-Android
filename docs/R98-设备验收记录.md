## FAIL：§7.1 顶部永恒点数未隐藏

截图 `android/reports/R98/06-1inf-gated.png`（1080×2400）实测仍显示：

- 顶部 **「你拥有 0 永恒点数。」** ← 应隐藏
- 底部动作行 **「永恒」** 圆按钮 ← 无限阶段不应出现
- 底部页签 **「时间」** ← 永恒层级页签，不应出现

### 根因（可信推断，有静态依据）

`work/base_decoded_321/smali_classes2/kajfosz/antimatterdimensions/MainActivity.smali:34923`：

```smali
iget-object v2, v0, Lkajfosz/antimatterdimensions/MainActivity;->t2:Landroid/widget/TextView;
invoke-static {}, Lf82;->j()Z
move-result v5
invoke-static {v2, v5}, Lq51;->E(Landroid/view/View;Z)V
```

原版**每帧**用 `f82.j()` 重设 `t2` 可见性。而 `f82.j()` 只读
`Player.eternities > 0 || f82.p()`，该字段在本版本可能被初始化为非零
（R94 实测新档读到 11）。因此：

1. MOD 侧一次性把 `t2` 置 `GONE`（`narrowed=1`）；
2. 同一帧内原版随后按 `j()=true` 把它重新显示；
3. 因为阶段未变化、脏标记已清，MOD 不再重试 → 最终停在"显示"。

即 R98 §1 点名的**「原版缓存/View 更新顺序错误」**：MOD 写入早于原版 UI 通道，
且只在事件时写一次，无法压过原版逐帧重设。

### 修复方向（下一轮）

门控必须在**主线程、原版 UI 通道之后**每帧对账（仅当目标 View 当前可见性错误时写入），
而不是只在阶段变化时写一次。需同时覆盖：

- 顶部永恒点数 `t2` / `0x7f0a05c6`
- 永恒统计块 `i6` / `0x7f0a05c8`
- 现实统计块 `o6` / `0x7f0a0e6a`
- 永恒页签 `jp4.p:Lll2;`
- 「时间」等永恒层级子页签、底部「永恒」动作按钮

`origE=unknown` 还需单独排查：`f82` 反射未解析成功，导致无法比对原版判据，
诊断日志失真（`eternitiesField=0` 也可能是读取失败被误记成 0）。

## 1. 顶部永恒点数：FAIL → PASS

**真实根因（已验证事实）**

- `work/base_decoded_321/smali/q51.smali:787-815`：`q51.E(View,Z)` 就是

## 1. 缺陷复现（FAIL → 已修复）

| 关闭后 8 秒 | `17-toggle-off-after8s.png` | **自动进行维度提升 / 自动购买反物质星系 / 计数频率自动提升 / 自动购买第一维度 全部被重新勾选 ✓**，仅自动大坍缩仍关闭 |

即玩家手动关闭后 **8 秒内**策略把 4 个自动器强行重开，
违反 R98 §5.3「不得强制重新打开玩家主动关闭的原版自动购买器」
与 `~/.dsh/AGENTS.md` §81.1 第 9 条「不强制开启玩家主动关闭的原版自动购买器」。

**根因（代码级，已验证）**

`OrekiStageAuto.reconcileManagedAutobuyer` 旧实现：

```kotlin
if (OrekiPlayerIntent.consumeManagedActiveRestoreDue(key)) {
    GameApi.setAutobuyerActive(autobuyer, true)   // ← 到点强行写回 true
    ...
} else {
    OrekiPlayerIntent.noteManagedActiveDisabled(key, ...)
}
```

它只比较「策略想要开 / 实际是关」，**没有"玩家关的"这一维度**，
因此到点即重开。R97 的 pending→restore 状态机被误用到 `isActive` 开关本身；
该状态机只应服务**受管配置值**（间隔、阈值、模式）。

## 2. 修复（Kotlin，根因级，无新增 Handler / 无轮询）

- `OrekiPlayerIntent.kt`：新增「玩家已关闭」一票否决闩锁
  `notePlayerClosed(key) / isPlayerClosed(key) / clearPlayerClosed(key) / clearAllPlayerClosed()`。
- `OrekiStageAuto.reconcileManagedAutobuyer` 改为三段语义：
  1. `active == true`（玩家自己重新打开）→ 解除闩锁，恢复接管；
  2. `!wantOn`（策略希望关闭）→ 清登记，不对抗；
  3. `wantOn && !active` → **登记一票否决，永不自动重开**，日志
     `managed[<key>]: player closed -> respect, no auto re-enable`。
- 受管**配置值**（大坍缩模式/间隔/阈值）的恢复路径**未改动**，仍按 §81.1 第 4–5 条在下一次策略 tick 恢复。

## 3. 构建期契约同步（Python，§6.4 允许范围内的必要兼容修改）

`scripts/build_mod.py:3146` 原有三条 `[R97]` 断言要求"受管自动器开关必须在策略恢复路径写回建议值"，
与新规则直接冲突，导致 `assembleRelease` 失败（`AssertionError: [R97] 受管自动器开关必须在策略恢复路径写回建议值`）。
按 §6.4「GUI 修复涉及 Python 构建工具时进行必要兼容修改」改为断言**新不变量**（不是删检查）：

```python
assert "OrekiPlayerIntent.notePlayerClosed" in sa_txt, (... 必须登记「玩家已关闭」一票否决 ...)
assert "OrekiPlayerIntent.clearPlayerClosed" in sa_txt, (... 玩家重新打开时必须解除闩锁 ...)
assert "GameApi.setAutobuyerActive(autobuyer, true)" not in sa_txt, (... 仍在强制重开 ...)
```
